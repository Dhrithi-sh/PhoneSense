# PhoneSense

A search engine for smartphones. Type a need like *"phone under $300 with good battery and
5G"* and get a ranked list of phones. It combines classic IR (TF-IDF, BM25, Boolean spec
filters, phrase search), neural IR (dense retrieval, Rocchio, HyDE, rank fusion), and
graph-based trust ranking (PageRank over a co-review graph, reviewer trust).

**Research question:** does trust-weighted ranking resist review manipulation (injected fake
reviews and reviewers) better than plain ranking, while keeping retrieval quality the same?

Information Retrieval final project. Deadline: **Sat 21 Nov 2026**. Submission: a ZIP of
this repo plus the report.

All file formats and interfaces are defined in **[CONTRACT.md](CONTRACT.md)**. Read it first.

## Reproduce

One command, from the processed data in `data/processed/` (the slow raw download and build
only with `FULL=1`):

```bash
make reproduce            # or: python scripts/reproduce.py
make reproduce FULL=1     # or: python scripts/reproduce.py --full
```

It runs: index → baselines (dev, test) → T06/T07 runs (dev, test) → Boolean efficiency →
eval → ablation → report numbers. Tuned parameters come from `config.yaml` (`bm25.tuned`,
`phrase.tuned`, written once by the dev-only tuning scripts `scripts/tune_bm25.py` and
`scripts/tune_phrase.py`), so reproduction never re-tunes on anything. Teammates' runs are
picked up from `runs/` if present; they are regenerated by their own scripts: B:
`scripts/run_dense.py`, `run_rocchio.py`, `run_hyde.py`, `tune_fusion.py`; C:
`scripts/run_rerank.py`, `run_attacks.py` (on their branches until merged). A step whose
inputs don't exist yet (e.g. no qrels) is reported and the rest still runs; the ablation then
shows those rows as pending.

Submission: `make submission` (`python scripts/make_submission.py`) builds
`dist/PhoneSense_submission.zip`, unzips it into a temp dir, runs the tests there, and writes
`SUBMISSION_CHECKLIST.md`.

## Evaluation protocol

* **45 queries** (`queries/queries.jsonl`), split into dev and test. All tuning (BM25 k1/b,
  BM25F weights, phrase weight, fusion weights, damping) uses **dev only**; test is evaluated
  once with the dev-chosen settings. The "best overall" ablation row is chosen on dev
  nDCG@10 (asserted in `scripts/ablation.py`).
* **Judgments:** graded 0–3 from an LLM judge over pooled runs, plus a human-labelled subset;
  agreement is reported as Cohen's kappa and linear weighted kappa
  (`phonesense/eval/agreement.py`, B's `scripts/kappa.py`).
* **Relevant = grade ≥ 2** for binary metrics; nDCG uses gains 2^grade − 1. **Unjudged =
  non-relevant**; judged@10 is reported for every run, and rows with judged@10 < 0.7 are
  flagged as lower bounds.
* **Significance:** paired randomization test (10,000 permutations) and paired t-test;
  Holm–Bonferroni across systems compared with the same baseline.

## Known limitations

* **Pool coverage:** qrels come from pooling, so systems that were not in the pool (or rank
  many unjudged phones high) are underestimated; see judged@10.
* **Null specs never match filters:** a phone with an unknown spec fails every constraint on
  it, even under `not`. Price is known for only about 23% of phones, so price filters remove
  most of the collection.
* **Prices are USD list prices** from the dataset snapshot, not current prices.
* **Rule-based constraint parser:** common price/RAM/storage/battery/screen/5G/OS phrases
  only; no negation, camera megapixels or brands (see "Filters").
* Pure-Python index and scoring: latencies are for a 7k-phone collection on one core.

## Data pipeline (T02)

Turns the raw Amazon Reviews 2023 `Cell_Phones_and_Accessories` files into the contract files
`data/processed/phones.jsonl` and `reviews.jsonl`. Code: `phonesense/data/`, settings and
URLs: `config.yaml` (`dataset.urls`, `dataset.fallback_urls`, `pipeline.*`).

```bash
python scripts/build_data.py                  # full run (= make data)
python scripts/build_data.py --limit 200000   # quick test on the first N raw lines (= make data-quick)
python scripts/build_data.py --force          # rebuild every stage instead of using the cache
python scripts/build_sample.py                # (re)write the 500-phone sample (= make sample)
python scripts/build_sample.py --limit 2000000  # sample from a partial run if the full run is slow
```

Stages (each `python -m phonesense.data.<stage>` also works on its own):

| Stage | What it does | Output |
|-------|--------------|--------|
| `download` | Fetches both raw files into `data/raw/`; skips files already there. UCSD mirror first, then Hugging Face (`McAuley-Lab/Amazon-Reviews-2023`, served as plain `.jsonl`, gzipped on the fly). If both fail it prints where to put a manually downloaded file (`.jsonl.gz` or `.jsonl`). | `data/raw/*.jsonl.gz` |
| `filter_phones` | Rule-based phone score: phone categories, phone-only `details` keys, brand+model / "smartphone" / "unlocked" / GB in the title (+); "case for", "compatible with <brand>", accessory words, tablet, watch, hotspot, lots (−). Keep if score ≥ `pipeline.filter_threshold`, then drop items with `rating_number` < `min_reviews`. | `filter_log.jsonl` (`parent_asin, kept, score, reasons`) |
| `parse_specs` | One regex function per spec field, priority `details` → title → features; units normalized, impossible values → null; source recorded. | `interim/specs.jsonl` |
| `dedupe` | Merges listings with the same (brand, model name, storage, refurbished); keeps the most-rated one. | `dedupe_log.jsonl` |
| `build_reviews` | Streams the reviews once, keeps reviews of candidate phones, remaps merged listings, drops empty texts and duplicates. | `interim/reviews_candidates.jsonl` |
| `build_phones` | Final phones (≥ `min_reviews` kept reviews), `rating_count`/`avg_rating` from kept reviews, `text = build_text(fields)`; writes the final reviews of those phones only. | `phones.jsonl`, `reviews.jsonl`, `phone_meta.jsonl` |
| `stats` | Counts, coverage, reviewer overlap (for the graph task), brands, prices. | `results/data_stats.json` |

* **Caching:** a stage is skipped if its outputs exist, are newer than its inputs, and were
  built with the same settings (`interim/manifest.json`). `--force` rebuilds everything.
* **`--limit N`** writes to `data/processed/partial_<N>/` (own stats and sample), so a test run
  never overwrites the full build.
* **Sidecar `phone_meta.jsonl`** (not a contract file): `refurbished` flag, filter score, the
  source of each parsed spec, merged listings, raw `details`. Same `doc_id`s as `phones.jsonl`.
* **Sample for teammates:** `data/processed/sample/{phones,reviews}.jsonl` = 500 phones
  stratified by brand (seed from config) + all their reviews. Data files are gitignored; share
  the sample folder directly.
* **Memory/runtime:** everything streams from the `.gz` files; the largest in-memory sets are
  the review-dedupe hashes and the per-reviewer map (a few hundred MB), so 8 GB RAM is
  enough. Measured on a laptop: download ~5 min (meta, 0.9 GB gz) + 15–60 min (reviews,
  depends on bandwidth); filter ~3 min; reviews pass ~10–15 min; `--limit 200000` ~1 min.

## Index & TF-IDF (T03, T04)

Our own positional inverted index (`phonesense/index/`) and an lnc.ltc TF-IDF retriever
(`phonesense/retrieval/tfidf.py`). No IR libraries: NLTK supplies only the Porter stemmer
algorithm (no corpus download). Index and weighting logic are adapted from our midterm project
(see [`legacy/PORTING.md`](legacy/PORTING.md)).

```bash
python scripts/build_index.py --sample                 # 500 phones -> data/index/sample/  (= make index-sample)
python scripts/build_index.py                          # full phones.jsonl -> data/index/  (= make index)
python scripts/run_tfidf.py --query "samsung 5g 128 gb"    # top 10 (doc_id, score, title)
python scripts/run_tfidf.py --split dev                # runs/tfidf_lnc.ltc_dev.run + latency (needs queries/queries.jsonl)
```

`build_index.py` skips the build when the saved index is up to date (`--force` rebuilds) and
writes `results/index_stats.json` (`index_stats_sample.json` for `--sample`): N, vocabulary,
postings and average length per field, build/load time, size with VB compression vs plain
uint32. `run_tfidf.py` prints mean/p95 query latency and writes
`results/latency_<run_name>.json`. Indexes live in `data/index/` (gitignored).

**Analyzer** (`analyzer:` in config.yaml, same for documents and queries): NFKC + lowercase;
units joined (`128 GB`/`128GB` -> `128gb`, `5,000 mAh` -> `5000mah`, `6.1"` -> `6.1in`,
`48 megapixel` -> `48mp`); model codes kept (`a54`, `13c`, `5g`); built-in stopword list
(never removes `5g 4g pro max plus mini ultra lite`); Porter stemming except for tokens with
digits. Positions keep gaps where stopwords were removed. Changing the analyzer config makes a
saved index stale: `load()` refuses it and prints the rebuild command.

**API for teammates** (`from phonesense.index import Analyzer, InvertedIndex, load_index`):

| Call | Returns |
|------|---------|
| `InvertedIndex.build(phones, analyzer, fields=FIELDS)` / `load_index(sample=False)` / `idx.save(path)` | index over fields `title`, `features`, `description`, `text` |
| `idx.N`, `idx.vocab_size(field)`, `idx.vocabulary(field)` | doc count, vocabulary |
| `idx.df(term, field="text")`, `idx.cf(term, field)` | document / collection frequency |
| `idx.postings(term, field)` | `[Posting(doc, tf, positions), ...]` sorted by internal doc id |
| `idx.doc_len(doc, field)`, `idx.avg_doc_len(field)` | lengths in indexed terms (for BM25) |
| `idx.doc_id(doc)`, `idx.doc_index(doc_id)` | internal int id <-> contract `doc_id` |
| `idx.term_vector(doc, field)` | `{term: tf}` forward index (Rocchio) |
| `idx.skip_pointers(term, field)`, `phonesense.index.intersect(p1, p2)` | sqrt(n) skips, AND of two postings lists (T07) |
| `idx.analyzer.analyze(text)` | query terms analysed exactly like the documents |

**lnc.ltc** (Manning et al., IIR ch. 6), term-at-a-time over postings, top k by heap, ties
by `doc_id`:

* document: `w(t,d) = 1 + log10 tf(t,d)`, cosine-normalized (no idf)
* query: `w(t,q) = (1 + log10 tf(t,q)) * log10(N / df_t)`, cosine-normalized; OOV terms skipped
* `score(q,d) = sum_t w(t,q) * w(t,d)`

`TfidfRetriever(field="text", index=idx)` reuses a loaded index; `TfidfRetriever().fit(phones)`
builds its own. The run name is `tfidf_lnc.ltc` (`tfidf_lnc.ltc.<field>` for other fields).

## Evaluation (T11)

Our own metric code in `phonesense/eval/` (no pytrec_eval / ranx in shipped code).

```bash
# one or more runs -> results/<run_name>.json (contract 4.9), summary printed
python -m phonesense.eval.cli eval --run runs/bm25_tuned_dev.run runs/dense_dev.run
# significance vs. a baseline (randomization + t-test, Holm over the systems)
python -m phonesense.eval.cli compare --baseline runs/bm25_tuned_test.run --runs runs/dense_test.run runs/rrf_bm25+dense_test.run --metric ndcg@10
# Markdown + LaTeX table (globs work in PowerShell too); dagger = significant vs. baseline
python -m phonesense.eval.cli table --results "results/*_dev.json" --metrics P@10 MAP nDCG@10 judged@10 --baseline tfidf_lnc.ltc --out results/table_dev.md
python -m phonesense.eval.cli agree --a qrels/human.txt --b qrels/llm.txt   # kappa (T09b)
python scripts/run_eval.py      # = make eval: every run in runs/ -> results/*.json + results/table_<split>.md
```

`--qrels` defaults to `qrels/qrels.txt` and falls back to `qrels/llm.txt` with a warning; the
split comes from the run name (`_dev` -> the dev queries in `queries/queries.jsonl`).

**Metrics** (per query, then the mean over queries):

| Name | Definition |
|------|------------|
| `P@k`, `R@k`, `F1@k` (k = 5, 10, 20) | relevant in top k / k; / all relevant; harmonic mean |
| `MAP` | mean of AP; AP = (1/\|rel\|) Σ P@r over the ranks r of relevant docs (per-query value = AP) |
| `nDCG@k` (k = 5, 10, 20) | DCG = Σ (2^grade − 1) / log2(rank + 1); ideal DCG from **all judged docs** of the query |
| `RR`, `R-prec` | 1 / rank of the first relevant doc; precision at rank R = \|rel\| |
| `judged@10` | fraction of the top 10 that has any judgment |

Conventions:

* **Relevant = grade ≥ 2** (`eval.relevance_threshold`, = `schemas.RELEVANCE_THRESHOLD`) for
  every binary metric; nDCG uses the graded values.
* **Unjudged documents count as non-relevant.**
* **Queries with no relevant document are excluded** from the averages and listed in the
  results `meta.excluded_qids` (queries with no judgments at all: `meta.unjudged_qids`). A
  scored query missing from the run gets zeros.
* **Always report judged@10.** Our qrels come from pooling: a run that was not in the pool
  has low judged@10, and its scores underestimate it.
* Significance: paired randomization test (10,000 permutations, two-sided, seed from config)
  and paired t-test; Holm–Bonferroni when one baseline is compared with several systems.
  Tables mark p_Holm < 0.05 with †.
* `phonesense.eval.plots.pr_curve` draws 11-point interpolated P–R curves into
  `report/figures/` (PNG + PDF).

## BM25 (T05)

`phonesense/retrieval/bm25.py`, on the shared inverted index:

* **BM25**: score = Σ_t w_q(t) · idf(t) · tf·(k1+1) / (tf + k1·(1 − b + b·dl/avgdl)), with
  idf(t) = ln(1 + (N − df + 0.5)/(df + 0.5)) (never negative). Each distinct query term
  counts once (`bm25.query_tf: once`), or (k3+1)·qtf/(k3+qtf) with k3 = 8 (`query_tf: k3`).
* **BM25F-lite**: Σ_f w_f · BM25_f, per-field BM25 with that field's lengths (default
  weights title 3, features 1.5, description 1). Separate run name `bm25f_...`.

```python
from phonesense.index import load_index
from phonesense.retrieval.bm25 import BM25Retriever, BM25FRetriever
idx = load_index()
BM25Retriever(k1=1.2, b=0.75, index=idx).score_text("samsung 5g 128 gb", k=10)
```

**Tuning protocol (dev only):**

```bash
python scripts/tune_bm25.py                   # = make tune
python scripts/run_baselines.py --split dev   # = make baselines: tfidf, bm25_default, bm25_tuned, bm25f_tuned
python scripts/run_baselines.py --split test  # ONCE, at the end, with the dev-chosen params
```

`tune_bm25.py` grids k1 ∈ {0.4, 0.6, …, 2.0} × b ∈ {0.0, 0.1, …, 1.0} on the dev queries
(objective `bm25.tuning.objective`, default nDCG@10), then the BM25F weights title ∈
{1, 2, 3, 5} × features ∈ {1, 1.5, 2} at the best k1/b. It writes `results/bm25_tuning.json`,
`report/figures/bm25_tuning_heatmap.{png,pdf}` and `bm25f_tuning_heatmap.{png,pdf}`, and the
best parameters into **`config.yaml` under `bm25.tuned`** (only the block between the
`BEGIN/END bm25.tuned` comments is rewritten; commit it). It refuses `--split test`, because
tuning on test would invalidate the test results. `run_baselines.py --split test` refuses to
overwrite existing test runs without `--force`.

## Filters (T06)

`phonesense/retrieval/filters.py`. Filters use the contract syntax (CONTRACT.md 4.4), checked
by `schemas.validate_filter`:

```json
{"and": [{"field": "price", "op": "<", "value": 300}, {"field": "has_5g", "op": "==", "value": true}]}
```

* **Null policy:** a phone whose spec is `null` never satisfies a constraint on it, **not even
  under `not`** (three-valued Kleene logic; a phone passes only if the whole filter is TRUE).
  This trades recall for precision: phones with missing specs drop out of filtered runs.
* **Filter source per query:** the query's own `filters` in `queries/queries.jsonl` if set,
  otherwise the rule-based parser `parse_constraints(text) -> (filter, residual_text)`. The
  source is logged in `runs/<run_name>.filters.json`.
* **Parser coverage:** price (`under/below/less than $X`, `up to $X`, `over $X`,
  `$X-Y`, `between X and Y`), RAM (`8gb ram`, `at least 6 gb ram`), storage (`128gb`,
  `256 gb storage`, `1tb`; a bare `Ngb` below 16 is RAM), battery (`5000 mah` -> `>=`),
  screen (`6.5 inch` -> ±0.2", `under 6 inches`, `compact`/`small` -> `<= 6.2`), `5g`,
  `android`, `ios`/`iphone`. Numeric specs mean "at least" (`8gb ram` -> `ram_gb >= 8`).
  **Not parsed:** "budget", "cheap", "big battery", camera megapixels, brands, negation.
  The matched phrases are removed and the rest of the query goes to the ranker.
* **Wrap any retriever:**

```python
from phonesense.retrieval.filters import FilteredRetriever
FilteredRetriever(bm25, phones, mode="pre")    # TF-IDF / BM25 / BM25F / phrase: filter inside the scoring loop
FilteredRetriever(dense, phones, mode="post")  # any retriever: top 1000, then filter
```

  Pre-filtered docs keep exactly their unfiltered scores. If fewer than k docs pass, fewer
  are returned (no padding).

## Boolean & phrase search (T07)

```python
from phonesense.retrieval.boolean import BooleanSearcher
from phonesense.retrieval.positional import phrase_matches, proximity_matches, PhraseBoostRetriever
BooleanSearcher(idx).search("samsung AND 5g AND NOT refurbished")   # doc_ids
BooleanSearcher(idx).search("(pixel OR iphone) AND NOT renewed", field="title")
phrase_matches(idx, "wireless charging")        # {doc: occurrences}, any field
proximity_matches(idx, "battery", "life", 3)    # within 3 positions, either order
```

* **Boolean syntax:** terms, `AND`, `OR`, `NOT`, parentheses; adjacent terms are ANDed;
  operators have equal precedence and apply left to right (`a OR b AND c` = `(a OR b) AND c`).
  AND operands are intersected smallest first, with sqrt(n) skip pointers.
* **Phrases** `"t1 t2"` match consecutive positions (stopword gaps are kept identically in
  queries and documents); **proximity** `t1 /k t2` matches `|pos1 − pos2| <= k`.
* **Phrase boost:** `PhraseBoostRetriever(bm25)` adds `phrase_weight · Σ ln(1 + matches)` for
  the query's quoted phrases and the auto-phrases in `phrase.auto_phrases`. `phrase_weight`
  is tuned on dev only.

```bash
python scripts/tune_phrase.py                 # dev only (refuses --split test) -> phrase.tuned in config.yaml
python scripts/run_t06_t07.py --split dev     # bm25_tuned(+filters)(+phrase) runs, table, compare, constraint subset
python scripts/run_t06_t07.py --split test    # ONCE
python scripts/bench_boolean.py               # AND latency with/without skip pointers -> results/efficiency.json
```

`run_t06_t07.py` writes `results/table_t06_t07_<split>.md`, `results/compare_t06_t07_<split>.json`
(Holm-corrected vs. `bm25_tuned` on nDCG@10 and MAP) and `results/filters_subset_<split>.{json,md}`
(metrics over queries with constraints vs. without).

## Add a new retriever in 5 steps

1. Create a branch (`git checkout -b t04-tfidf`) and a module, e.g. `phonesense/retrieval/tfidf.py`.
2. Subclass `Retriever`: set `name` (e.g. `"tfidf_lnc.ltc"`) and implement
   `fit(phones)` and `search(query, k) -> [(doc_id, score), ...]` (score descending).
3. Load inputs through the contract: `io.read_phones(get_path("phones"))`,
   `io.read_queries(get_path("queries"), split="dev")`.
4. Write the run with `run_retriever(retriever, queries)`, which creates `runs/tfidf_lnc.ltc_dev.run`.
   Score it with `python -m phonesense.eval.cli eval --run runs/tfidf_lnc.ltc_dev.run`
   (writes `results/tfidf_lnc.ltc_dev.json`; compare against BM25 with the `compare` command).
5. Add a test on the fixtures (`tests/fixtures/phones.jsonl`), run `make test && make lint`,
   and open a PR to `main`.
